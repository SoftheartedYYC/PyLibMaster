Three sibling sub-packages with strict dependency direction: `system/` provides foundational services (logging via `logManager.js`, environment detection via `envManager.js`, file explorer, updater) with no dependencies on `config/` or `operations/`; `config/` manages persistent JSON state through `configManager.js` plus `mirrorManager.js` and `schedulerManager.js`, depended on by both `system/` and `operations/`; `operations/` implements high-level business logic (`pipManager.js` ~1600 lines orchestrating install/uninstall/update with parallelism, multi-mirror retry, environment-level mutex locks, and automatic backup/rollback via `backupManager.js`) and depends on both `config/` and `system/`. Each manager follows a CommonJS module-pattern export of pure functions with in-memory caching. Cross-cutting concerns are centralized: process execution goes through `../../utils/processRunner`, logging through `../system/logManager`, and all disk writes use atomic temp-file-then-rename patterns.
