Tests are organized into two layers: (1) focused unit tests in `core.test.js`, `installPackages.test.js`, and `installPackages.runCommand.test.js` that exercise individual modules with per-test mock injection; (2) a monolithic `stress.test.js` that bootstraps a shared `mockState` object and injects fake implementations of `processRunner`, `envManager`, `configManager`, `mirrorManager`, `backupManager`, `logManager`, `undoManager`, `templateManager`, and `auditManager` via `require.cache` replacement before each `describe` block. A top-level `bootstrap.js` preloads the Electron mock from `mocks/electron.js` so Node's built-in test runner can load Electron-dependent modules without an actual Electron runtime. Each test group follows a `resetMockState → removeMocks → injectMocks` lifecycle, creating temp directories under `os.tmpdir()` and cleaning them up in `afterEach`. Cross-cutting concerns like mirror retry logic, parallel install serialization, backup/rollback, and path security validation are exercised through the same injected mock surface across both unit and stress suites.
