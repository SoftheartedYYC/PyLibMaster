The app follows the standard Electron three-process model: `main.js` is the single entry point that creates the BrowserWindow (with contextIsolation=true and nodeIntegration=false), loads `renderer/index.html`, and registers every IPC handler via `ipcMain.handle`. `preload.js` is the only bridge between renderer and main — it exposes a single `window.electronAPI` object whose methods each call `ipcRenderer.invoke` with a namespaced channel (`pip:*`, `env:*`, `mirror:*`, `backup:*`, `config:*`, `updater:*`, `scheduler:*`, `template:*`, `audit:*`, `undo:*`, `explorer:*`). The main process imports the `core/` modules directly (pipManager, mirrorManager, envManager, backupManager, logManager, configManager, updater, venvManager, schedulerManager, templateManager, auditManager, undoManager, explorerManager) and delegates each IPC handler to the appropriate manager. Long-running operations push progress back to the renderer via `event.sender.send('pip:progress', ...)` or `mainWindow.webContents.send(...)`, while one-way events like `theme:changed`, `updates:available`, and `scheduler:executed` flow from main to renderer. The renderer calls into this API without ever touching Node APIs directly, keeping the core module isolated in the main process.
