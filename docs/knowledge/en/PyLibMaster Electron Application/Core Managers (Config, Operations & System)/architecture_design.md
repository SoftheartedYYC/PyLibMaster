The module is organized into three sibling sub-packages with a clear dependency direction: `system/` provides foundational services (logging, environment detection, file explorer, updater) that have no dependencies on `config/` or `operations/`; `config/` manages persistent state via JSON files through `configManager.js` and is depended on by both `system/` and `operations/`; `operations/` implements high-level business logic (pip operations, audit, backup, templates, undo, venv) and depends on both `config/` and `system/`. Each manager follows a module-pattern export of pure functions with in-memory caching (e.g., `lastScanResult` in auditManager, `cachedEnvironments` in envManager, `mirrors` in mirrorManager). Cross-cutting concerns are centralized: process execution goes through `../../utils/processRunner`, logging through `../system/logManager`, and all disk writes use atomic temp-file-then-rename patterns. The `pipManager.js` is the largest component (~1600 lines) and orchestrates install/uninstall/update with parallelism, multi-mirror retry, environment-level mutex locks (`acquireEnvLock`), and automatic backup/rollback via `backupManager`.
